# 2026-07-31 Worker 修复总结

## 根因概览

Worker 启动不了 → 修图效果不对 → 图片显示不出来。三个问题环环相扣，逐个排查修复。

---

## 一、Worker 启动问题

### 1. 缩进错误（P0）
- **Bug**: `worker.py` 第 464 行 `_try_refresh_token` 函数体没缩进，`IndentationError`
- **修复**: 修正函数体缩进，`_try_cached_token` 加回 class 内部 4 空格
- **文件**: `mangaGo-worker/worker.py`

### 2. pythonw.exe 无法启动
- **现象**: 双击 `start.bat` 窗口闪退
- **原因**: `pythonw.exe` 无控制台，`start ""` 方式路径解析有问题
- **修复**: `start.bat` 改用 `python.exe`（带控制台，方便看日志）

---

## 二、Worker 状态机 Bug（云端 backend）

### 3. Worker 崩溃后任务卡死
- **Bug**: `poll` 只查 `status == 'pending'`，Worker 崩溃后任务永远卡在 `running`
- **修复**: 改为 `status.in_(['pending', 'running'])`
- **文件**: `comic-backend/bulePrint/workerBp.py:70`

### 4. OCR 无文字时 translateStatus/retouchStatus 卡 pending
- **Bug**: `submitBatch` 无文字图片 `translateStatus = 'pending'`、`retouchStatus = 'pending'`，永远"待翻译""待修图"
- **修复**: 无文字时直接设 `translateStatus='done'`、`retouchStatus='done'`
- **文件**: `comic-backend/bulePrint/workerBp.py`

### 5. 修图失败 retouchStatus 不更新
- **Bug**: `submitBatch` 修图失败只在 batches JSON 里标 failed，数据库 `retouchStatus` 仍为 pending
- **修复**: 补 `img.retouchStatus = 'failed'`，并加入 `affected_chapters` 触发章节状态更新
- **文件**: `comic-backend/bulePrint/workerBp.py`

### 6. submit 修图异常 NameError
- **Bug**: ``base64.b64decode` 抛异常时 `img` 未赋值，`except` 块里 `if img:` 触发 `NameError`
- **修复**: try 前预置 `img = None`
- **文件**: `comic-backend/bulePrint/workerBp.py`

### 7. 章节状态聚合不生效（P0）
- **Bug**: `status_aggregator.py` 里 `update_chapter_status` 用 `with app.app_context()` 创建了新 session（Flask-SQLAlchemy 3.x 按 context 隔离），看不到 `submitBatch` 外层 session 里还没 commit 的图片状态变更
- **修复**: 去掉嵌套 `app.app_context()`，复用调用方的 session
- **文件**: `comic-backend/services/status_aggregator.py`

### 8. _agg 把 failed 视为终态
- **Bug**: `_agg` 遇到 `{'done', 'failed'}` 返回 `'failed'`，章节永远不显示"完毕"
- **修复**: `done`/`no_text`/`failed` 统一视为终态 → 返回 `'done'`
- **文件**: `comic-backend/services/status_aggregator.py`

## 三、修图管线 Bug

### 9. Worker 修图效果差（P0）
- **根因 1**: 旧 Worker 调用翻译服务 `/review/render-direct`，传入 `font_scale_factor=0.65`，字体太小
- **根因 2**: 翻译服务内置渲染 vs 本地 AOT 的 Pillow 自定义渲染，效果不同
- **最终方案**: Worker 直接 `import` 本地 AOT 函数 `call_local_retouch_aot_service`，走完全相同的管线
- **文件**: `mangaGo-worker/worker.py`

### 10. 修图过滤空译文
- **Bug**: `comicCrawlImageModel.getImagesWithCorrectedTranslationByChapterId` 过滤条件 `!= ''` 和 `!= '[]'` 漏掉了 `[""]` 和 `["",""]`
- **修复**: 补 `!= '[""]'`、`!= '["",""]'`
- **副作用发现**: `skip_completed` 过滤 `retouchStatus != 'completed'`，但枚举值为 `'done'`，过滤永远无效
- **修复**: 改为 `retouchStatus.notin_(['done', 'no_text'])`
- **文件**: `comic-backend/model/comicCrawlImageModel.py`

### 11. HTTP 回退路径参数未对齐
- **Bug**: `_retouch_via_http` 传 `font_scale_factor=0.65`，和 AOT 不一致
- **修复**: 改为 `font_scale_factor=3.0` + `font_size_offset=15` + `text_merge` + `mask_expand_ratio=0.05`
- **文件**: `comic-backend/bulePrint/comicCrawlRetouchBp.py`

### 12. retouch_local_aot 缺少 WORKER_MODE import
- **Bug**: 第 1313 行用 `WORKER_MODE` 但没 import，报 `NameError` 500
- **修复**: 加 `from config import WORKER_MODE`
- **文件**: `comic-backend/bulePrint/comicCrawlRetouchBp.py`

### 13. 修图后 updatedAt 不更新
- **Bug**: `submitBatch` 更新 `translatedImageUrl` 但 MySQL `onupdate` 没触发，`?t=` 时间戳不变
- **修复**: 显式 `img.updatedAt = datetime.datetime.now()`
- **文件**: `comic-backend/bulePrint/workerBp.py`

## 四、翻译管线 Bug

### 14. 翻译解析不兼容嵌套数组

- **修复**: 加 `elif isinstance(item, list):` 分支
- **文件**: `comic-backend/bulePrint/async_translate_worker.py`

## 五、基础设施问题

### 15. Docker ps_images 丢失（P0）
- **Bug**: `ps_images` 没有 Docker 卷挂载，每次 `docker compose up -d --build` 容器重建时旧修图文件全丢
- **修复**: docker-compose.cloud.yml 加 `ps_images:/app/ps_images` 持久化卷
- **附带**: nginx `ps_images` 缓存改为 `expires -1`

### 16. Cloudflare CDN 缓存旧 404
- **Bug**: ps_images 文件重建后，Cloudflare 缓存旧的 404 响应 4 小时
- **修复**: `to_dict` 返回 `translatedImageUrl` 时加 `?t={updatedAt}` 时间戳参数
- **文件**: `comic-backend/entity/ComicCrawlImage.py`

### 17. config.py dotenv 导致云端 502
- **Bug**: `config.py` 直接 `from dotenv import load_dotenv`，云端没装 python-dotenv → `ModuleNotFoundError` → 502
- **修复**: 改为 `try/except ImportError` 可选导入
- **文件**: `comic-backend/config.py`
- **附带**: 加 `.env` 文件本地设 `WORKER_MODE=0`

## 最终架构

```
云端管理后台 "批量本地修图"
  │
  └→ WORKER_MODE=1 → 创建 pending BatchCrawlTask
                          │
                          └→ Worker(本地) 轮询取走
                               │
                               └→ call_local_retouch_aot_service()  ← 和本地 AOT 同一函数
                                    │
                                    ├── AOT-GAN 擦除
                                    ├── 碰撞合并文字块
                                    └── Pillow 自定义渲染
                                         │
                                         └→ base64 → submitBatch → 云端 ps_images（持久卷）
                                                                       │
                                                                       └→ ?t=时间戳 → 破 CDN 缓存
```

- **Worker = 薄调用层**：只轮询、下载、调本地 AOT 函数、上传结果
- **所有渲染逻辑**：在 `comic-backend/bulePrint/comicCrawlRetouchBp.py` 中，唯一入口
- **ps_images 持久化**：Docker 卷挂载，部署不丢
- **缓存破坏**：时间戳参数，文件更新立即可见

### 18. 修图输出 PNG→WebP
- **优化**: AOT 输出从 PNG 改为 WebP(Q85)，文件从 ~210KB 降到 ~30KB，加载速度提升 7 倍
- **注意**: 需要同时改 `_vie.png` → `_vie.webp` 的文件命名（comicCrawlRetouchBp + workerBp）
- **文件**: `comic-backend/bulePrint/comicCrawlRetouchBp.py`, `comic-backend/bulePrint/workerBp.py`

### 19. ps_images bind mount 修复
- **Bug**: bind mount 配置丢失，Docker 写容器内、nginx 读宿主机，两个目录不同步
- **修复**: 重新配置 `- /opt/comic-platform/comic-backend/ps_images:/app/ps_images`，迁移文件
